# 详细说明

这里是 [README](../README.md) 之外的完整规则：修改记录、选区与识别、预览、定位信息和架构。

## 修改记录与回滚

**记录什么**

- 只对从本地 HTML 发起的修改建立记录。发送或放入输入框前保存原内容：HTML、关联 CSS、CSS 导入、图片和字体，以及本轮原生文件工具即将修改的其他文件。
- 要求进入当前会话的对应轮次后开始跟踪，轮次结束时保存修改结果。宿主变更列表若报告未备份或重命名的文件，整批停用回滚。
- 先「放入输入框」时记录显示「等待开始」，发送后关联实际执行的轮次。不再发送可以在记录中移除；在同一会话发起新的修改也会替换它。两者都不改动项目文件。若被替换的旧请求仍和新请求在同一条消息里发出，新记录会标明不能单独回滚。

**不建立记录的情况**

以下情况请求照常发送或放入输入框，同时提示「本次没有修改记录，不能一键回滚」及原因：

- 会话正在运行：排队的消息可能被归到正在运行的那一轮，无法确定修改前的状态。
- 同一会话已有正在执行或保存对比的记录。
- 文件超出记录上限（见下），或文件超出当前会话工作区。
- 记录已满，且没有可以自动删除的已结束记录。

只有选区已经过期（原文件或关联文件在选择之后被改过）时才会拦下请求，并保留已填写的要求，请重新选择。

**上限与自动清理**

- 文件每份最多 4 MiB，HTML 最多 1 MiB，单侧最多 33 个文件、16 MiB。
- 每个会话最多 10 条记录，全部会话合计最多 40 条、约 64 MiB（未结束的记录按修改前内容的两倍估算）。
- 超出时自动删除已结束的记录：先删已回滚的，再删「记录未完成」的，最后按结束时间删最旧的。等待开始、正在执行和正在回滚的记录不会被删除。会话各自计数，一个会话的记录不会挤掉另一个会话的。

**回滚**

- 只恢复普通 UTF-8 文字文件，保留 BOM、CRLF 等原始内容。已删除的原文字文件只在路径仍为空时重新创建。新增文件、变动的二进制资源和不完整的记录会明确提示并停用回滚，不会只恢复一部分却宣称完成。
- 回滚前先核对整批文件，再通过宿主的版本条件逐个写回。文件在本轮结束后又被编辑时显示具体冲突并停止；写入途中失败时标出已恢复的文件，剩余文件可以重试。
- 同一工作区（包括上级或下级目录）有会话正在运行时，回滚会等本轮结束；其他文件夹中的会话不影响回滚。工具执行前，只等待工作区重叠的记录保存完对比。
- 无 Git 的工作区中，宿主可能列不出命令行改动的额外文件，回滚范围以面板列出的文件为准。插件不使用 Git reset，不重置整个工作区。

**对比与存储**

- 对比是冻结内容的静态预览，不执行页面脚本，不代表 hover、弹窗或登录状态，也不是系统截图。静态预览中的链接不可点击。
- 已结束、已回滚或「记录未完成」的记录保存在本机应用数据目录（Windows 为 `%APPDATA%\dsh-region-edit\history`），不写入项目文件夹，相同内容只存一份。尚未发送或正在执行的请求不保存，重启后需要重新发起。
- 重启后回滚会逐字节核对文件仍是当时修改后的内容，一致才写回。
- 启动时清理确定已损坏的记录（无法解析或缺少内容文件）、残留的临时文件和不再被引用的内容文件。只清理 10 分钟前的文件，以免影响另一个窗口正在写入的内容；读取暂时失败（例如文件被占用）的记录和它的内容会保留。

## 选区与识别

- 文字、Markdown、代码和带可读文字层的预览：按文字的实际排版位置逐字判断是否在轮廓内，不按外接矩形混入轮廓外的文字。祖先完全透明或被滚动容器裁剪隐藏的文字不会提交。
- 图片：保存自由轮廓在原图中的像素坐标和归一化坐标。PNG、JPEG、WebP、GIF 通过宿主原生视觉输入识别，发送修改时附带原图。SVG 等其他预览提供文件引用和自由轮廓。在图片外的留白处圈选会提示重选。
- 识别使用当前会话的模型和现有登录，只返回对象名称、文字和不确定性，不执行编辑，也不向聊天发送消息。自动识别模式下，每次圈选或重新识别产生一次模型请求。识别失败时可以手动填写目标。
- **轮廓标记图（可选，默认关闭）**：勾选后，插件从原图文件的像素生成一张长边不超过 1280 像素的 JPEG，轮廓外调暗，轮廓用白底红线描出。它随识别请求作为第二张图发给视觉模型；发送修改时作为第二个图片附件，提示模型只用来定位、不要编辑它。标记图不是屏幕截图，与预览的缩放无关。原图无法解码时自动退回只发原图。选择保存在本机，下次打开仍然有效。
- PDF、Office 转换预览取决于宿主是否渲染了可读的文字层，发送原文件路径、选中文字和能获取到的页码，不声称能定位二进制文件的源码行。
- 调整窗口或预览大小后旧选区失效，已写的要求会保留。「重选」会重新读取文件版本和源码。手动指定的目标在重选后保留为待确认的草稿，点「重新识别」才恢复自动识别。轮廓自相交时会提示沿目标外围重画。

## 圈选预览

- 只加载本地文件和本地关联资源，不访问网络。依赖 CDN、远程接口、嵌套框架、动态模块导入或内联事件处理器的页面，请用宿主原来的预览方式。页面脚本是否运行仍受 Harness 的代码工作工具开关控制。
- 本地 CSS 支持背景图、WOFF/WOFF2/TTF/OTF 字体和嵌套 `@import`，相对路径按引用它的样式表解析。所有关联文件并行读取；循环引用的样式表只跳过重复的那条引用。最多 32 个关联文件，每个不超过 4 MB，合计不超过 16 MB，这些文件会加入宿主的文件变化监听。
- 链接保留 `href`，`:link` 和 `a[href]` 样式照常生效。点击链接不会离开预览；页内锚点 `#id` 会滚动到目标。
- `<picture>` 显示其中的 `<img>`；只有 `srcset` 的图片使用 1x 候选（没有就用第一个）。修改记录按同样的规则保存图片。
- 预览始终以标准模式渲染（HTML 规范规定 `srcdoc` 框架不进入怪异模式），没有 doctype 的旧页面在浏览器中可能显示得不同。

## 定位信息

- **源码位置**：内置解析器在资源改写前记录每个开始标签的行列，能区分文字相同的元素；浏览器自动补出的节点不伪造行号。精确映射限 1 MiB 文本、最多 12,000 个有原始标签的节点。启用页面脚本时，脚本可能提前替换节点，这类页面不提供精确行号；之后新增或克隆的节点也不会继承原节点的位置。
- **层级**：点中按钮、链接、label 或 SVG 内部时，先选中外面的整体；「选择内层」沿实际点中的路径逐层向内，「选择外层」逐层向外。
- **样式**：当前视口下的 21 项关键计算属性、按层叠顺序最后匹配的至多 8 条规则、至多 12 个被引用的 CSS 变量和一层父容器布局。规则从最后加载的样式表倒序查找，大型框架之后的自定义样式也能找到。支持 CSS 嵌套（`&`、嵌套声明、嵌套的 `@media`），按源码写法显示，例如 `.card { &:hover }`。`@container`、`@scope`、`@layer` 中的规则标出所在条件，`:hover`、`:focus`、`:active` 等交互状态的规则也会列出并标明所需状态；这些条件是否成立不做判断。直接加载的 CSS 会注明文件，内嵌或导入样式中无法确认的来源不猜文件或行号。这不是完整的层叠分析，不覆盖伪元素等全部规则。
- **发给模型的数据**：点选元素时不发送屏幕坐标和视口尺寸；有源码位置时不再重复附带元素的序列化 HTML；父容器只保留布局属性；取初始值的属性（如 `margin: 0px`、`line-height: normal`）和空字段省略。面板里的「定位信息」仍显示全部内容。
- 发送前重新核对文件版本、元素身份和提取内容，有变化时保留要求并提示重选。

## 架构

- 一个桌面插件包：界面复用宿主 React，通过公开的 `slots`、`documentPreviews`、`sessions`、`workspaceFiles`、`attachments` 和 `llm` 接口工作。没有独立服务、系统截图通道、另一套模型 API 或额外运行依赖。
- 宿主端提供可取消的只读识别方法和修改记录接口。修改记录只通过宿主带版本条件的文件系统写回。
- 鼠标轨迹用 SVG 显示并保留为多边形，精简采样点后逐字判断文字是否与轮廓相交。图片把轮廓直接映射到原图。识别请求通过宿主的 Connection/Remote 通道绑定当前会话；取消、重选、卸载和超时都会结束请求。外接范围只用于摆放面板，不替代自由轮廓。
- 隔离预览通过 `MessageChannel` 只提供只读的圈选、点选和元素查询，保持 `sandbox="allow-scripts"`、不授予 `allow-same-origin`，并用 CSP 禁止网络连接。来自预览的数据有形状和大小校验；源码行号从父页面保存的解析索引补入，不接受 iframe 自报的行号。这个通道没有读取文件、发送会话或执行宿主命令的权限。
- 客户端到宿主的 RPC 只传无损 JSON，标记图因此以 base64 传输，宿主端校验为限定大小内的 JPEG。
- `dsh.client.platform: "web"` 是 Harness 桌面端共用界面加载器的名称；插件会检查桌面桥接对象，在独立 Web 客户端中不启用。
